# 점검 결과

**Policy → Findings**는 현재 구현된 명세 점검에서 확인한 차이를 보여줍니다. 민감정보 탐지 자체를 위반으로 판정하는 화면은 아닙니다.

## 현재 점검

| 점검 ID | 검사 내용 | 실패 근거 |
|---|---|---|
| `api_endpoint_documented` (SPEC-001) | 관측한 메서드·경로가 기준 명세에 있는가 | 명세에 없는 관측 API |
| `api_response_fields_documented` (SPEC-002) | 수집한 JSON 응답 필드가 응답 스키마에 있는가 | 명세에 없는 응답 필드 |

## 빠른 검토

1. Run scan을 완료합니다.
2. Findings에서 점검·서비스·상태로 범위를 좁힙니다.
3. API의 근거와 이유를 확인합니다.
4. API 상세의 Fields와 Calls를 열어 실제 차이를 검토합니다.
5. 잘못된 명세·서비스 배정·필드 매핑을 수정한 뒤 다시 스캔합니다.

## 상태 읽기

- **Pass**: 검사한 관측 자료에서 해당 조건을 충족했습니다.
- **Fail**: 비교 가능한 근거에서 조건 불일치를 확인했습니다.
- **Not evaluated**: 명세·관측·응답 스키마·수집 본문 등이 부족하거나 독립적 기준이 없습니다.

트래픽에서 추론한 명세는 같은 트래픽의 준수 평가에 쓰지 않습니다. 응답 필드 점검은 자료형·필수값·권한·실제 개인정보 제공 적법성을 검증하지 않습니다.
