# PoC 진행 가이드

한 서비스와 짧은 로그 구간부터 시작해, 탐지 품질과 근거를 확인한 다음 연결 범위를 넓힙니다.

## 1. 범위 정하기

검증할 서비스·게이트웨이·수집 기간을 정합니다. 성공 기준은 API 식별 수, 명세 밖 API 검토, 민감 필드의 근거, 미검사 사유 등으로 구체화합니다. 자동 규정 준수 판정을 성공 기준으로 삼지 않습니다.

## 2. 입력 준비

| 입력 | 확인할 내용 |
|---|---|
| OpenAPI | 공식 계약인지, 코드·관측에서 만든 초안인지 |
| 코드 | 대상 브랜치·커밋, 서비스 ID 매핑, 게이트웨이 설정 |
| 로그 | 시각·메서드·경로·상태, 서비스 구분, 헤더·본문 수집 여부 |
| 수집 계정 | 필요한 저장소·인덱스·HDFS 경로를 읽는 권한 |

## 3. 한 경로를 끝까지 확인

1. 서비스와 준비된 명세·코드를 등록합니다.
2. 로그 연결을 Test하고 필드 매핑을 검토합니다.
3. Run scan을 실행합니다.
4. 알려진 API 한 개를 골라 Spec / Code / Log와 요청·응답 필드를 대조합니다.
5. 합성 민감 값의 기대 탐지·비탐지 사례를 확인합니다.
6. 룰 수정 후 자동 재분류가 전체 적용 범위에 반영되는지 확인합니다.

## 4. 결과 검토

오탐·미탐은 유형, API, 필드 경로, 출처, 기대 결과, 실제 결과와 근거를 함께 기록합니다. 검사 불가를 미탐과 섞지 말고 미수집·미지원·한도 초과를 별도로 셉니다. 화면의 호출 200건을 원본 전체 호출의 표본 크기로 오해하지 마세요.

## 5. 확장과 인계

서비스 배정·별칭·경로 prefix를 검토한 뒤 다른 소스를 추가합니다. 인계할 때 기준 커밋, 활성 룰 버전, 수집 범위, worker 구성, 원문 캐시와 백업 보관 방식을 기록하세요. [현재 제한](../reference/limitations.md)을 결과 보고서에 포함합니다.
