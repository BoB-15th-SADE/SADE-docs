# 보안 검토 자료

SADE는 기업 내부망에 설치합니다. 로그 본문의 값, 인증 헤더, 토큰은 저장하지 않고, 분석 자료를 밖으로 보내지 않습니다.

로그인 기능은 없고, 대시보드는 기본으로 설치 서버에서만 열립니다.

## 한눈에 보기

| 질문 | 답 |
|---|---|
| 어디에 설치하나요 | 기업 내부망의 서버 한 대에 Docker 컨테이너로 설치합니다 |
| 트래픽 경로에 들어가나요 | 들어가지 않습니다. 요청을 가로채거나 막지 않고, API를 호출해 점검하지 않습니다. 명세 주소를 허용한 경우에만 그 주소에서 명세 파일을 받아 옵니다 |
| 요청, 응답 본문을 저장하나요 | 값은 저장하지 않습니다. 저장 전에 값을 타입(`<string>` 등)으로 바꾸고, 찾은 민감 유형 이름만 남깁니다 |
| 밖으로 자료를 보내나요 | 보내지 않습니다. 밖으로 나가는 연결은 이용자가 직접 연결한 GitHub, Kafka, 허용한 명세 주소뿐입니다 |
| 소스 코드를 가져가나요 | 복제(clone)하지 않습니다. GitHub API로 필요한 파일만 읽고, 분석 결과(API, 파일 위치, 호출 관계)만 저장합니다 |
| 로그인이 있나요 | 없습니다. 대시보드는 기본으로 설치 서버에서만 열립니다. [접속 통제](#access) 참고 |

## 저장하는 것과 저장하지 않는 것

| 구분 | 내용 |
|---|---|
| 저장함 | 호출 시각, 서비스, 서버 이름, 메서드, 경로, 응답 코드, trace ID, 출발지 IP와 `X-Forwarded-For`, 필드 이름과 타입, 민감 유형 이름 |
| 저장함 (코드) | API 선언 위치(파일, 줄), 서비스 사이 호출, 인증 선언, CODEOWNERS 담당 후보, 핸들러 코드의 커밋 번호와 작성자 GitHub 아이디 |
| 저장하지 않음 | 요청, 응답 본문의 값, 민감정보 값과 그 위치, 인증 헤더, 토큰, 비밀번호, 쿠키 값, 소스 코드 원문 |

!!! warning "경로와 IP는 원래 값 그대로 남습니다"
    경로에 개인정보를 넣는 서비스(예: `/users/kim@example.com`)라면 그 경로가 로그 표에 남습니다. 출발지 IP도 원래 값으로 저장합니다. 이런 서비스는 로그를 보내기 전에 경로를 가리거나, 보관 기간을 줄입니다.

자세히: [로그 처리와 값 가리기](../how-it-works/log-processing.md)

## 보관과 삭제

| 자료 | 기본 보관 | 바꾸는 곳 |
|---|---|---|
| 값을 가린 로그 줄 | 30일 | `.env`의 `SADE_LOG_RETENTION_DAYS` |
| API별 날짜별 호출 수 | 400일 | `.env`의 `SADE_LOG_DAILY_RETENTION_DAYS` |
| API 최초 발견, 마지막 호출 시각 | 로그 줄이 지워진 뒤에도 유지 | |

### 지우는 방법

- CSV 업로드 하나: CSV 업로드 화면의 최근 업로드에서 데이터 삭제
- 소스 하나 전체(CSV, syslog, Kafka): Log Sources 연결된 소스 탭의 저장된 로그 지우기
- 코드 스캔 결과: Source Code > 스캔 결과 탭에서 선택 항목 삭제
- 전체: 설치 폴더에서 `docker compose down -v` (모든 데이터 볼륨 삭제, 되돌릴 수 없음)

## 네트워크

### 받는 연결

| 포트 | 쓰임 | 기본 열림 범위 | 바꾸는 곳 |
|---|---|---|---|
| 443 (HTTPS) | 대시보드 | 이 서버(`127.0.0.1`)만 | `SADE_HTTPS_BIND`, `SADE_HTTPS_PORT` |
| 6514 (TCP, TLS) | syslog 수신 | 모든 주소. 방화벽으로 보내는 서버만 허용해야 합니다 | `SADE_SYSLOG_PORT` |
| 1514 (TCP, UDP) | 평문 syslog. 기본은 꺼져 있음 | 이 서버(`127.0.0.1`)만 | `SADE_SYSLOG_PLAIN_BIND`, `SADE_SYSLOG_PLAIN_PORT` |

### 나가는 연결

| 목적지 | 언제 | 비고 |
|---|---|---|
| 이미지 저장소 | 설치, 업데이트할 때 | 이미지를 미리 받아 두면 운영 중에는 필요 없습니다 |
| GitHub (HTTPS 443) | 코드 스캔을 연결했을 때 | GitHub.com, Enterprise Cloud, Enterprise Server |
| Kafka 브로커 | Kafka를 연결했을 때 | 읽기만 합니다 |
| 명세 주소 | `SADE_SPEC_FETCH_ALLOWED_URLS`에 적은 주소만 | 기본은 꺼져 있습니다 |

나머지 컨테이너(backend, worker, PostgreSQL, ClickHouse)는 호스트에 포트를 열지 않습니다. Docker 내부 네트워크에서만 닿습니다.

API 상세의 코드 위치 링크는 이용자 브라우저에서 GitHub 페이지를 엽니다. SADE 서버가 거는 연결이 아닙니다.

## 인증 정보 보관

| 인증 정보 | 보관 위치 | 보호 |
|---|---|---|
| GitHub 토큰 | PostgreSQL | `SADE_SECRET_KEY`로 암호화합니다. 화면, API 응답, 로그에 내보내지 않습니다 |
| Kafka 비밀번호, 클라이언트 키 | `kafka-secrets` 볼륨 | 암호화하지 않은 파일이며, 파일 권한 600으로 둡니다. backend와 Vector 컨테이너만 이 볼륨을 붙입니다(Vector는 읽기 전용). 저장 뒤 화면에 다시 보여 주지 않습니다 |
| DB 비밀번호, `SADE_SECRET_KEY` | 설치 폴더의 `.env` | 서버 관리자가 파일 권한으로 막습니다. 저장소에 올리지 않습니다 |
| 대시보드 TLS 인증서 | `nginx-certs` 볼륨 | 처음 실행할 때 자체 서명 인증서를 만듭니다. 기업 인증서로 바꿉니다 |

GitHub 토큰은 스캔할 저장소의 읽기 권한(Contents: Read-only)만 줍니다. Kafka는 읽을 토픽과 컨슈머 그룹의 읽기 권한만 줍니다.

## 접속 통제 {#access}

| 사실 | 지금 버전의 동작 |
|---|---|
| 로그인과 권한 관리 | 없습니다. 대시보드에 접속한 사람은 누구나 모든 결과를 보고 연결과 설정을 바꿉니다 |
| 대시보드 기본 열림 범위 | 설치 서버(`127.0.0.1`)에서만 열립니다. 다른 PC에서 열려면 `SADE_HTTPS_BIND`를 바꾸고 방화벽으로 접속 주소를 제한합니다 |
| syslog 수신(6514) | 보내는 쪽을 인증하지 않습니다. 이 포트에 닿는 누구나 로그를 넣어 결과를 바꿀 수 있어, 방화벽으로 보내는 서버만 허용합니다 |

## SADE가 판정하지 않는 것

- 취약점과 법 위반. 관리 우선순위는 검토 순서입니다.
- 요청이 실제로 막히는지. 인증은 코드와 명세의 선언만 읽습니다.
- 수집하지 않은 기간과 서비스. 근거가 없으면 "모름"이나 "미평가"로 남기고 안전으로 세지 않습니다.

자세히: [지원 범위와 제한](../reference/limitations.md), [동작 원리](../how-it-works/index.md)

## 검토용 체크리스트

- [ ] 설치 서버와 망 위치를 정했다
- [ ] 대시보드를 다른 PC에서 연다면 방화벽으로 접속 주소를 제한했다
- [ ] 6514를 보내는 서버 IP만 허용했다
- [ ] `.env`의 비밀번호와 `SADE_SECRET_KEY`를 새로 만들었다
- [ ] 로그 보관 기간을 사내 기준에 맞췄다
- [ ] 경로에 개인정보를 넣는 서비스가 있는지 확인했다
- [ ] GitHub 토큰과 Kafka 계정을 읽기 권한으로만 받았다
- [ ] 대시보드 인증서를 기업 인증서로 바꿨다
