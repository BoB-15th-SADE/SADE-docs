# 마스킹과 데이터 보관

SADE는 수집한 로그의 원문 값을 저장하지 않습니다. 이 페이지는 무엇이 어디에 얼마나 남는지 정리합니다. 왜 이렇게 설계했는지는 [값을 남기지 않는 저장](../technology/value-free-storage.md)에 있습니다.

## 저장되는 것

| 자료 | 저장 방식 |
|---|---|
| 수집 배치 | 본문·헤더 값은 타입(`<string>` 등), 요청 ID·trace ID는 해시, 경로 ID는 경로 틀. 최근 20개 배치를 보관하고, 실행 중인 검사가 쓰는 배치는 지우지 않음 |
| 대용량 Splunk 소스 | API별 호출 집계 + API·상태별 대표 요청 5개 (값 없음) |
| 호출 기록 | 최근 1,000건 (값 없음) |
| 클라이언트 IP, X-Forwarded-For | 원문 그대로 (포트만 뗌) |
| 민감정보 탐지 결과 | 위치, 유형, 신뢰 등급, 검사 상태, 규칙 버전. 원문 값 없음 |
| Cloudera 체크포인트 | 파일별 마지막 읽은 위치 |
| 연결 토큰 | DB의 별도 secrets 영역. 화면, 내보내기, 작업 입력에 나오지 않음 |
| 명세, 코드 인벤토리, 설정, 작업 이력 | 비교와 재분석에 필요한 만큼 |

## 화면에 보이는 값

| 표시 | 뜻 |
|---|---|
| `<string>`, `<integer>`, `<number>`, `<boolean>` | 원래 값의 타입. 실제 값은 저장하지 않음 |
| `<JWT>`, `<Bearer>` | 인증 헤더에서 읽은 방식 |
| `(empty)` | 빈 값이 기록됨 (인증 없이 보낸 경우 등) |
| `(not recorded)` | 로그가 그 값을 남기지 않음 (`-`) |
| `[REDACTED_KEY]` | 데이터를 키로 쓰는 응답에서 가린 키 |

명세의 Example은 명세에 적힌 예시일 수 있습니다. 실제 호출 값으로 읽지 마세요.

## 예전 버전에서 업그레이드했다면

예전 버전은 Splunk 이벤트 원문을 `source_evidence` 캐시에 소스당 최대 10 MB까지 저장했습니다. 이 캐시는 자동으로 지우지 않습니다. 아래 명령으로 남은 건수를 확인하고, 보관 정책에 따라 처리하세요.

```bash
docker compose exec api python -m sade_cli doctor
```

새 PoC는 새 데이터 폴더로 시작하는 것을 권장합니다.

## 백업

```bash
docker compose exec api python -m sade_cli backup --output /workspace/apps/dashboard/data/poc-backup.db
```

SQLite backup API로 일관된 사본을 만들고 무결성을 확인합니다. 기존 파일을 덮어쓰지 않습니다. 백업에는 연결 토큰이 들어 있으므로 운영 DB와 같은 수준으로 관리하세요.

## 운영 시 정할 것

- 자동 보관 기간이나 만료 삭제는 아직 없습니다. DB, 백업, 입력 로그의 보관 기간을 따로 정하세요.
- DB 파일은 암호화된 비밀 저장소가 아닙니다. 데이터 폴더의 접근 권한을 관리하세요.
- 클라이언트 IP는 원문으로 남습니다. 고객 정책상 가려야 하면 사전에 합의하세요.
