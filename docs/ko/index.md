# SADE란

SADE는 **로그, OpenAPI 명세, 소스코드**를 함께 분석해 기업이 운영 중인 API를 식별하고,
응답 본문 필드와 개인정보 흐름까지 가시화하는 **방법론과 도구**입니다.

## 왜 필요한가

- 기업은 운영 중인 API 전체를 파악하지 못합니다. 문서화되지 않은 API, 폐기됐지만 호출되는 API가 남아 있습니다.
- 명세가 있어도 응답 본문에 실제로 어떤 필드가 오가는지는 정리돼 있지 않습니다.
- 개인정보가 어느 API에서 나가고, 어떤 서비스를 거쳐 외부로 전달되는지 보이지 않습니다.

## SADE의 접근 방법

| 단계 | 방법 | 결과 |
|---|---|---|
| API 식별 | 로그, OpenAPI 명세, 소스코드를 하나의 엔드포인트 단위로 결합 | 요청, 응답 본문 필드까지 포함한 API 명세 |
| 민감정보 식별 | 사전 정의 룰과 커스텀 룰 | 개인정보를 다루는 API와 필드 |
| 흐름 가시화 | 코드의 호출 관계, 로그의 추적 ID | 서비스 간 호출 경로 |
| 정책 적용 | 제3자 제공 등 정책을 룰로 작성 | 정책과 다른 전송 정황 |

## 알 수 있는 것과 알 수 없는 것

- 알 수 있는 것
    - 수집 기간에 실제로 호출된 API와 필드
    - 명세와 실제 호출의 차이
    - 개인정보로 보이는 필드와 그 위치
- 알 수 없는 것
    - 로그에 남지 않은 정보 (본문을 남기지 않으면 본문 필드는 판단할 수 없음)
    - 수집 기간 밖의 호출
    - 탐지 결과는 정황이며, 위반의 최종 판단은 담당자가 합니다.
