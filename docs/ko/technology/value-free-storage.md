# 값을 남기지 않는 저장

개인정보를 찾는 도구가 개인정보를 또 쌓아 두면 그 자체가 새로운 유출 경로가 됩니다. SADE는 로그의 값을 **메모리에서만 판단에 쓰고**, 저장할 때는 값을 지운 근거만 남깁니다. 그래도 나중에 규칙을 바꿔 다시 분석하고, 원본 로그의 위치를 찾아갈 수 있게 설계했습니다.

## 언제 지우나

<div class="sade-pipe" markdown>
<div markdown>**읽기**<p>SIEM·파일에서 원문 로그</p></div>
<div class="is-key" markdown>**메모리에서 판단**<p>값 형식 검증, 인증 방식, 필드 타입</p></div>
<div markdown>**봉인**<p>값을 타입과 해시로 바꿈</p></div>
<div markdown>**저장**<p>수집 배치 (SQLite)</p></div>
</div>

값이 필요한 판단(주민등록번호 구조 검증, JWT 형식 확인, 필드 타입 판단)은 수집 중에 메모리에서 끝냅니다. 그 결과만 남기고 원문은 저장 전에 버립니다.

## 무엇이 어떻게 남나

| 원래 값 | 저장되는 것 | 예 |
|---|---|---|
| 본문 값 | 필드 경로와 타입 | `"email": "user@example.com"` → `"email": <string>` |
| 헤더 값 | 타입. Content-Type 같은 안전한 헤더만 원문 | `authorization: Bearer eyJ...` → `<string>`, 인증 방식은 `JWT`로 따로 |
| 빈 값 | 빈 값 그대로 | `authorization: ""` → `(empty)`. 가려도 숨길 게 없고, 인증 없이 보낸 사실을 보여 줌 |
| 쿼리 값 | 이름만 남기고 값은 타입 | `?email=a@b.com` → `?email=<string>` |
| 경로의 ID | 경로 틀 | `/customers/a@b.com` → `/customers/{email}` |
| 요청 ID, trace ID, span ID | 해시 | 같은 요청끼리 잇는 데는 그대로 쓸 수 있음 |
| 원본 위치 | 해시 + Splunk `_cd`·인덱스·시각, HDFS 파일·위치 | 원본 로그를 다시 찾아갈 수 있음 |
| 클라이언트 IP, X-Forwarded-For | **원문** (포트만 뗌) | 보안 담당자가 호출자를 추적해야 함 |
| 민감정보 판단 결과 | 유형, 위치, 신뢰 등급, 적용 규칙, 검사 상태 | 값은 없음 |
| DB span | 시스템, DB 이름, 연산 이름 | 쿼리 문장, 파라미터, 결과는 버림 |

데이터 자체를 객체 키로 쓰는 응답(`{"user@example.com": {...}}`)은 키도 값처럼 다뤄 `[REDACTED_KEY]`로 바꿉니다.

## 값이 없어도 다시 분석할 수 있는 이유

| 다시 하는 일 | 필요한 것 | 저장된 결과로 가능? |
|---|---|---|
| 데이터 유형 별칭·문맥 규칙을 바꿔 재분류 | 필드 경로, 같은 객체의 필드 이름 | 가능 |
| 명세를 바꿔 다시 점검 | 필드 경로와 타입, 인증 방식 | 가능 |
| 요청 하나의 경로 다시 잇기 | 해시된 ID, span 관계 | 가능 |
| 값 검증 규칙(예: 새 정규식)을 새로 적용 | 원래 값 | **다시 수집 필요** |

규칙을 바꾸면 가벼운 재분류 작업이 저장된 결과로 다시 계산합니다. SIEM에 접속하지 않습니다. 값 검증이 새로 필요하면 이전 판단을 "오래된 후보"로 보존하고, 새 Value matched는 다시 수집할 때까지 만들지 않습니다.

## 토큰과 비밀

- Splunk·WebHDFS 토큰, GitHub 토큰은 설정과 다른 별도 영역에 저장합니다. 화면, 내보내기, 작업 기록, 오류 메시지, 명령줄에 나오지 않습니다.
- 토큰을 저장할 때의 주소·전송 방식·인증 방식이 바뀌면 그 토큰을 다시 쓰지 않습니다.
- DB 파일은 암호화된 비밀 저장소가 아닙니다. 데이터 폴더의 접근 권한을 관리해야 합니다.

## 예전 데이터

이 방식 이전 버전이 남긴 원문 캐시(`source_evidence`)는 자동으로 지우지 않습니다. `sade_cli doctor`가 남은 건수를 알려 주므로 담당자가 보관 정책에 따라 처리합니다. 새 PoC는 새 데이터 폴더로 시작하는 것을 권장합니다.

## 한계

- 값을 남기지 않으므로 화면에서 실제 값을 확인할 수 없습니다. 실제 값이 필요하면 SIEM에서 원본 위치로 찾아갑니다.
- 마스킹 이전 단계(WIRE)인지, 이미 가려진 로그(LOG_REDACTED)인지는 운영자가 소스 설정에서 지정해야 정확해집니다. 기본은 UNKNOWN입니다.
