# 핵심 기술

SADE는 서로 다른 세 가지 근거, **로그·명세·코드**를 같은 API 단위로 맞춰서 "어떤 API가 있고, 무엇을 주고받고, 어디로 흐르는지"를 보여 줍니다. 이 섹션은 그 과정을 기능별로 설명합니다. 사용 방법이 궁금하면 [연동 가이드](../connect/logs.md)를 먼저 보세요.

## 전체 흐름

<div class="sade-pipe" markdown>
<div markdown>**수집**<p>SIEM·파일에서 로그를 읽고, 코드·명세를 등록</p></div>
<div markdown>**정규화**<p>형식이 다른 로그를 같은 레코드로 맞춤</p></div>
<div class="is-key" markdown>**API 식별**<p>경로를 명세·코드의 API에 맞추고 출처를 붙임</p></div>
<div markdown>**분석**<p>민감정보, 명세 차이, 서비스 간 흐름</p></div>
<div markdown>**저장**<p>원문 값을 지운 근거만 보관</p></div>
</div>

**Collect now**가 수집부터 저장까지를, **Run scan**이 저장된 결과로 명세 점검을 다시 합니다. Run scan은 외부 시스템에 다시 접속하지 않습니다.

## 세 가지 근거의 차이

| 근거 | 알 수 있는 것 | 알 수 없는 것 |
|---|---|---|
| **Spec** (명세) | 서비스가 받기로 한 요청과 응답의 모양 | 실제로 호출되는지, 누가 부르는지 |
| **Code** (코드) | 구현된 API, 코드가 보내는 호출, 선언된 권한 검사 | 실제로 실행되는지, 얼마나 자주인지 |
| **Log** (로그) | 실제 호출, 횟수, 인증 방식, 주고받은 필드 | 수집 기간 밖의 호출, 로그에 안 남은 본문 |

SADE는 이 차이를 숨기지 않습니다. 모든 API와 필드에 `Spec` / `Code` / `Log` 출처를 붙이고, 근거가 없는 것은 "없음"이 아니라 "미관측"이나 "Not evaluated"로 표시합니다.

## 원칙

- **추측하지 않습니다.** 짝지을 후보가 여럿이면 잇지 않고, 경로를 알 수 없으면 "미확정"으로 남깁니다.
- **실행하지 않습니다.** 코드는 읽기만 하고, 서비스에 요청을 보내지 않습니다.
- **값을 남기지 않습니다.** 판단에 필요한 처리는 메모리에서 끝내고, 저장할 때는 타입과 근거만 남깁니다.
- **다시 계산할 수 있습니다.** 저장된 근거로 규칙을 바꿔 재분석할 수 있고, 같은 입력에서는 같은 결과가 나옵니다.
